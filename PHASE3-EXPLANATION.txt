1. DOCKERIZATION 🐳
================================================================================

What I Did:

A. Backend Dockerfile (backend/Dockerfile)
------------------------------------------
- Multi-stage build to optimize image size:
  
  Stage 1 (Builder): 
    - Uses python:3.11-slim as base
    - Installs build tools (gcc, g++, build-essential)
    - Installs ALL Python dependencies including:
      - FastAPI, Uvicorn (web server)
      - Transformers, PyTorch (ML models - largest dependencies ~2GB)
      - Sentence-transformers (embeddings)
      - PostgreSQL drivers (psycopg)
      - pgvector support
  
  Stage 2 (Runtime):
    - Fresh python:3.11-slim image (no build tools)
    - Copies only installed packages from Stage 1
    - Copies application code
    - Creates non-root user (appuser) for security
    - Sets up health check endpoint (/health)
    - Exposes port 8000
    - Final image: ~1.5GB (most is PyTorch)

Why multi-stage? 
- Build tools add ~500MB but aren't needed at runtime
- Smaller image = faster deployment, less storage cost
- More secure (no compilers in production)

B. Frontend Dockerfile (frontend/Dockerfile)
--------------------------------------------
- Multi-stage build for Nuxt.js:
  - Stage 1: Builds the production bundle
  - Stage 2: Serves pre-built static files
  - Uses Node.js 20 Alpine (minimal size ~150MB)
  - Non-root user for security
  - Health check on port 3000

C. Docker Compose (docker-compose.yml)
--------------------------------------
This orchestrates 3 services:

1. Database (db):
   - Image: pgvector/pgvector:pg16 (PostgreSQL with vector support)
   - Port: 5432
   - Volume: postgres_data (persists data between restarts)
   - Health check: pg_isready command
   - Network: triage-network

2. Backend (backend):
   - Builds from: backend/Dockerfile
   - Port: 8000
   - Depends on: db (waits for DB health check)
   - Volumes: 
     - ./backend/app (hot reload in dev)
     - huggingface_cache (saves ~2GB of model downloads)
   - Environment: All settings via .env file
   - Health check: curl http://localhost:8000/health
   - Restart policy: unless-stopped

3. Frontend (frontend):
   - Builds from: frontend/Dockerfile
   - Port: 3000
   - Depends on: backend
   - Environment: API base URL
   - Restart policy: unless-stopped

Key Features:
- Service dependencies: Frontend waits for backend, backend waits for DB
- Health checks: Ensures services are actually ready, not just started
- Named volumes: Data persists even if containers are deleted
- Bridge network: Services can talk to each other by name (e.g., http://backend:8000)
- Environment variables: Configurable via .env file

D. Environment Configuration (.env.docker)
------------------------------------------
Template with all required variables:
- Database credentials
- API settings (CORS origins, log level)
- HuggingFace model names
- Classification thresholds
- AWS S3 settings (optional)

2. CI/CD PIPELINE ⚙️ (GitHub Actions)
================================================================================

The Pipeline File: .github/workflows/ci.yml

This is a 5-job pipeline that runs automatically:

TRIGGERS:
- Push to: main, develop branches
- Pull requests to: main, develop branches

JOB 1: test-backend ✅
----------------------
What it does:
1. Spins up a PostgreSQL service container (pgvector image)
2. Checks out your code
3. Sets up Python 3.11
4. Installs dependencies from requirements.txt
5. Runs pytest with coverage:
   - All tests in backend/tests/
   - Generates coverage report (XML + terminal)
6. Uploads coverage to Codecov (optional)

Environment:
- DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/triage
- APP_ENV=test

Fails if: Any test fails or coverage drops below threshold

JOB 2: test-frontend ✅
-----------------------
What it does:
1. Checks out code
2. Sets up Node.js 20
3. Installs npm dependencies (with caching)
4. Builds frontend: npm run build

Fails if: Build fails (TypeScript errors, missing dependencies, etc.)

JOB 3: lint ✅
--------------
What it does:
1. Checks out code
2. Sets up Python 3.11
3. Installs Ruff (fast linter) and Black (formatter)
4. Runs Ruff: checks for code quality issues
5. Runs Black: checks code formatting

Fails if: 
- Linting errors (unused imports, syntax issues)
- Code not formatted with Black

JOB 4: build-and-push 🐳
-------------------------
When it runs: Only on push to main branch, after tests pass

What it does:
1. Checks out code
2. Sets up Docker Buildx (advanced builder)
3. Logs into GitHub Container Registry (ghcr.io)
   - Uses GITHUB_TOKEN (automatic, no setup needed)
4. Builds backend image:
   - Tags: latest, main-<commit-sha>
   - Uses layer caching for speed
   - Pushes to: ghcr.io/davidfragoso18/support-ticket-triage-system-backend
5. Builds frontend image:
   - Same tagging strategy
   - Pushes to: ghcr.io/davidfragoso18/support-ticket-triage-system-frontend

Result: 
- Your Docker images are published to GitHub Container Registry
- Anyone can pull them: docker pull ghcr.io/davidfragoso18/...
- Versioned by commit SHA (rollback capability)

JOB 5: deploy-aws ☁️ (Optional)
--------------------------------
When it runs: Only on push to main, after images are built

IMPORTANT: This job is DISABLED BY DEFAULT because it requires AWS secrets!

To enable:
1. Set up AWS infrastructure first (using infra/setup-aws.sh)
2. Add these secrets to GitHub repo settings:
   AWS_ACCESS_KEY_ID
   AWS_SECRET_ACCESS_KEY
   AWS_REGION (e.g., us-east-1)
   EC2_HOST (your EC2 public IP or domain)
   EC2_USER (ubuntu)
   EC2_SSH_KEY (content of triage-key.pem)

What it does when enabled:
1. Configures AWS credentials
2. SSHs into your EC2 instance
3. Runs these commands on EC2:
   cd /home/ubuntu/support-ticket-triage-system
   git pull origin main
   docker-compose down
   docker-compose pull  # Gets latest images from ghcr.io
   docker-compose up -d
   docker system prune -af  # Cleanup old images
4. Waits 30 seconds
5. Verifies deployment: curl http://EC2_HOST:8000/health

Fails if: 
- SSH fails
- Health check fails after deployment

3. AWS INFRASTRUCTURE ☁️
================================================================================

A. Automated Setup Script (infra/setup-aws.sh)
-----------------------------------------------

What it creates:

1. VPC (Virtual Private Cloud)
   - CIDR: 10.0.0.0/16
   - DNS hostnames enabled
   - Isolated network for your resources

2. Internet Gateway
   - Allows internet access for EC2

3. Subnets (2)
   - Subnet 1: 10.0.1.0/24 in us-east-1a
   - Subnet 2: 10.0.2.0/24 in us-east-1b
   - Required for RDS (needs 2 availability zones)

4. Route Table
   - Routes internet traffic through gateway
   - Associated with both subnets

5. Security Groups (2)
   - Backend SG: 
     - Ports: 22 (SSH), 80 (HTTP), 443 (HTTPS), 8000 (API), 3000 (Frontend)
     - Source: 0.0.0.0/0 (internet)
   - Database SG: 
     - Port: 5432 (PostgreSQL)
     - Source: Backend SG only (internal only!)

6. RDS Database
   - Engine: PostgreSQL 16.1
   - Instance: db.t3.micro (~$15/month)
   - Storage: 20GB SSD (encrypted)
   - Multi-AZ: No (for cost savings)
   - Backup retention: 7 days
   - Publicly accessible: No (security!)
   - Extension: pgvector (for embeddings)

7. S3 Bucket
   - Name: triage-attachments-<timestamp>
   - Versioning enabled
   - Lifecycle policy: Delete old versions after 30 days
   - CORS enabled for web uploads

8. EC2 Instance
   - Instance type: t3.medium (2 vCPU, 4GB RAM) ~$30/month
   - AMI: Ubuntu 22.04 LTS (latest)
   - Storage: 30GB EBS
   - Public IP: Auto-assigned
   - Elastic IP: No (would cost extra)

9. SSH Key Pair
   - Creates triage-key.pem
   - IMPORTANT: Save this securely!

Output:
- Saves all IDs to infra-config.sh
- Prints connection strings
- Shows estimated monthly cost: ~$50

Time to complete: ~10 minutes

B. EC2 Setup Script (infra/setup-ec2.sh)
-----------------------------------------

Run this ON the EC2 instance after creation:

1. System updates
   - apt-get update && upgrade
   - Security patches

2. Installs Docker
   - Uses official Docker installation script
   - Adds ubuntu user to docker group

3. Installs Docker Compose
   - Latest version from GitHub releases
   - Makes it executable

4. Installs utilities
   - Git, AWS CLI, htop, curl, wget
   - PostgreSQL client (for debugging)

5. Sets up firewall (UFW)
   - Allows ports: 22, 80, 443, 8000, 3000
   - Enables firewall

6. Creates swap file
   - 2GB swap (t3.medium has 4GB RAM)
   - Helps with ML model loading

7. Configures Docker daemon
   - JSON logging with rotation
   - Max log size: 10MB
   - Max files: 3

8. Creates systemd service
   - Auto-starts Docker Compose on boot
   - Service name: triage.service

9. Sets up automatic security updates
   - Unattended-upgrades package
   - Auto-applies security patches

Time to complete: ~5 minutes

C. Nginx Configuration (infra/nginx.conf)
------------------------------------------

Optional but recommended for production:

Features:
- HTTP to HTTPS redirect
- SSL/TLS termination (Let's Encrypt)
- Reverse proxy to backend (port 8000)
- Reverse proxy to frontend (port 3000)
- Security headers:
  - HSTS (force HTTPS)
  - X-Frame-Options (prevent clickjacking)
  - X-Content-Type-Options (prevent MIME sniffing)
  - X-XSS-Protection
- WebSocket support (for future real-time features)
- Gzip compression
- Custom timeouts for ML inference (60s)
- Access logs

Setup:
sudo apt install nginx certbot
sudo certbot certonly --standalone -d yourdomain.com
sudo cp infra/nginx.conf /etc/nginx/sites-available/triage
sudo ln -s /etc/nginx/sites-available/triage /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

D. CloudWatch Monitoring (infra/cloudwatch-config.json)
--------------------------------------------------------

Optional monitoring setup:

Metrics collected:
- CPU usage (idle, iowait)
- Memory usage (percent)
- Disk usage (percent)
- Network stats (TCP connections)

Logs collected:
- /var/log/syslog
- /var/log/nginx/access.log
- /var/log/nginx/error.log

Sends to CloudWatch every 60 seconds

Setup:
wget https://s3.amazonaws.com/amazoncloudwatch-agent/ubuntu/amd64/latest/amazon-cloudwatch-agent.deb
sudo dpkg -i amazon-cloudwatch-agent.deb
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
  -a fetch-config -m ec2 -s -c file:///path/to/cloudwatch-config.json

Cost: ~$5/month for logs + metrics

   └─> Run: infra/setup-aws.sh
       ├─> Creates all AWS resources

   └─> On EC2:

       └─> Services start:
           ├─> PostgreSQL (local Docker)
           ├─> Backend (connects to RDS in production)
           └─> Frontend (connects to backend)

   └─> git push origin main

   ├─> Job 1: Run backend tests ✅
